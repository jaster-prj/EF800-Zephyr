# EF800 C Source Ownership Inventory

Inventory baseline: repository tree and checked-in CMake/Twister manifests inspected on 2026-11-11; configured build metadata and ownership counts refreshed on 2026-11-12. The six image compile databases are generated from the configured Zephyr targets and listed in `analyzer-evaluation.md`. They confirm current translation-unit membership for those image configurations. Native-sim test compile databases were generated by Twister for all 26 test configurations. `application/plugins/measurement-plugin` host and native-package builds were configured separately; the native package images use custom compile commands rather than compile-database entries.

## Target manifest map

Zephyr and external-module sources brought in through `find_package(Zephyr)`, `ZEPHYR_EXTRA_MODULES`, or module include directories are not EF800-owned and must be classified as external during analysis.

## EF800-authored tests

`tests/shared/*/CMakeLists.txt` and `testcase.yaml` define the native-sim ztest compositions. The 22 EF800 test translation units are:

| Test target directories | Main test source |
|---|---|
| `backup_mtp`, `battery_soc`, `boot_update`, `composition`, `core`, `keyboard_update`, `lcd_contrast`, `measurement`, `metadata`, `persistence`, `plugin`, `ports`, `regression`, `rtc`, `ui` | `src/main.c` in each named directory; the CMake files add shared implementations selectively. |
| `virtual_display`, `virtual_keyboard`, `virtual_log`, `virtual_plugin`, `virtual_profile`, `virtual_protocol`, `virtual_serial`, `virtual_startup`, `virtual_storage`, `virtual_supervisor`, `virtual_usb` | `src/main.c` in each named directory; these test EF800 virtual adapters/contracts and add shared implementations as declared by each CMake file. |

The `keyboard` test configuration has no separate C file; `tests/shared/keyboard/CMakeLists.txt` applies `EF800_TEST_KEYBOARD` and includes `tests/shared/domain.cmake`, which compiles the shared `tests/shared/regression/src/main.c` test suite with keyboard/domain sources. Thus there are 22 checked-in test `.c` files but a test configuration can compile a translation unit from a different directory.

`application/plugins/measurement-plugin/CMakeLists.txt` defines additional EF800-authored host C tests: `tests/test_plugin.c`, `tests/test_dummy_calculation.c`, and `tests/test_worker_sdk.c`; `tests/test_native_package.c` is conditionally compiled by the native-sim package configuration. The host tests include plugin-owned source and common plugin runtime/protocol sources. These C tests are in the maintainability scope even though they are not Twister targets.

## Plugin package and auxiliary source classes

The measurement-plugin project builds separate deliverables with its own CMake configuration:

- Production plugin package inputs: `elta3/src/elta3.c`, `elta3/descriptor.c`, `fts3xx/src/fts3xx.c`, `fts3xx/descriptor.c`, `calculation-dummy/random_position.c`, `calculation-dummy/descriptor.c`, `common/protocol.c`, `common/plugin_runtime.c`, and `common/freestanding.c`; selected common/SDK pieces are linked into the package. These EF800-maintained C sources are owned artifacts and must be assessed under their actual freestanding ARM or native-sim configuration.
- Optional recovery-acceptance packages: `recovery-test/calculation_plugin.c` and `recovery-test/descriptor.c`; these are conditionally compiled test fixtures, not normal production plugins.
- `tests/test_native_package.c` is included by `PM_BUILD_NATIVE_SIM`; its runtime CTest currently fails on an unhandled fake worker operation, as recorded in `analyzer-evaluation.md`.

Additional application C projects discovered in the repository but outside the six firmware-image scope are classified separately rather than silently folded into those image inventories:

- `application/ef800-hwdebug`: 11 EF800-authored hardware diagnostic sources; development/diagnostic target, not one of the six images.
- `application/ef800-isolation-spike`: 4 sources including a dummy plugin; architectural spike, not a production image.
- `application/tlx-711a`: 4 LCD/emulator utility sources; its `t6963_emulator.c` is reused by MainApplication native-sim.
- `application/ef800_usb_sample` and `application/test-usb-mtp`: one source each, sample/diagnostic targets.

These auxiliary projects should be separately included or explicitly excluded in the final compliance policy according to the defined EF800-owned scope; they are not third-party code.

## Ownership and exclusions

- `boards/` contains EF800 board descriptions, Kconfig, Devicetree, YAML bindings, and CMake integration; there are no checked-in `.c` files under `boards/` at this baseline. EF800-owned C compiled via a board manifest elsewhere remains in scope.
- The source scan found no generated/DO NOT EDIT C translation units in `application/`, `shared/`, `boards/`, or `tests/`. Generated build outputs (including Devicetree output and the CGROM header) are not source-owned C and must be explicitly excluded from the EF800-authored source result.
- Zephyr, CMSIS, STM32 HAL, ZephyrMTP, PluginManager, and other west/CMake dependencies are external source ownership. Their headers may appear in compiler commands; that does not make their implementation EF800-owned. Analyzer system-header policy and macro expansion behavior must be documented rather than addressed with broad suppressions.
- The tree-wide baseline scan found 153 `.c` files across `application/`, `shared/`, `boards/`, and `tests/`: 53 under `application/`, 78 under `shared/`, zero under `boards/`, and 22 under `tests/`. The application total includes the six images, plugin package/test sources, and the auxiliary projects classified above. File counts are not compile membership; the per-target CMake manifests control that distinction.
