## Why

The current T6963C emulator is tied to the EF800's 8 KiB, 40-column, 6x8 display and implements only a subset of the controller command set. Its fixed model and simplistic framebuffer updates limit confidence in text/graphics composition, register behavior, custom characters, and native-sim display output. This change makes the emulator configurable and more faithful while preserving the EF800's packed one-bit framebuffer contract.

## What Changes

- Add configurable T6963C memory capacity, hardware geometry, font width, text/graphics areas, and character-generator behavior.
- Emulate the register and command behavior needed for address movement, text and graphics RAM, auto-read/write, cursor state, modes, attributes, screen operations, and bit operations.
- Keep the framebuffer one bit per pixel and update it incrementally from dirty display regions when RAM or display state changes.
- Compose textual and graphical register-derived output using T6963C OR, EXOR, AND, attribute, cursor, and blink behavior.
- Publish the existing complete 240 x 64 packed framebuffer only when incremental rendering changes at least one pixel.
- Add behavioral tests for configurable profiles, command semantics, readback, composition, and dirty rendering.

## Capabilities

### New Capabilities

- `t6963-display-emulation`: Configurable T6963C register, memory, rendering, and packed framebuffer behavior.

### Modified Capabilities

- `native-sim-ef800-peripherals`: Strengthen the LCD emulator contract used by the production native-sim composition.
- `virtual-ef800-platform`: Require the virtual LCD to expose frames generated by configurable, incremental T6963C behavior without changing the EF800 transport contract.

## Impact

- Affected implementation areas include `application/tlx-711a`, `shared/ef800_virtual`, and the T6963C driver integration.
- Native-sim and standalone TLX display builds will share the configurable emulator model while retaining the EF800 default profile.
- The existing packed framebuffer transport remains compatible; internal emulator APIs and tests will change.
- No hardware qualification claims or physical T6963 timing behavior are added.
